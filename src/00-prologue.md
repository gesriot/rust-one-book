# ПРОЛОГ: ПЕРВЫЙ ЗАПУСК

## Почему Rust

Два часа ночи. Твой терминал только что выплюнул Segmentation fault (core dumped). Где-то в недрах монолитной кодовой базы какая-то функция освободила буфер, пока другой поток продолжал его жадно читать. Тебе до боли знаком этот ритуал. Ты открываешь отладчик, мучительно выслеживаешь висячие указатели и накладываешь патч. Пушишь исправление. Выдыхаешь.

А потом все рушится. Твой патч породил тонкую гонку данных, которая заявит о себе в Черную пятницу, когда система окажется под пиковой нагрузкой.

Это налог на производительность. Мы десятилетиями обменивали рассудок на контроль над железом, выбирая либо комфорт языков со сборщиком мусора, либо опасную близость к регистрам, где каждый шаг – риск выстрелить себе в ногу. Но представь, что выбирать больше не нужно. Мир, где один инструмент одинаково хорош для всего: от мигающего светодиода на микроконтроллере до распределенного кластера, обрабатывающего миллионы запросов в секунду. От системного ядра до веб-интерфейса в браузере.
Это не утопия. Это Rust. (И нет, это не секта. Хотя, если честно, иногда похоже.)

Rust решает фундаментальную проблему программирования: как получить полный контроль над железом, не внося катастрофические ошибки с каждым релизом. Три механизма делают это возможным:

**Borrow checker** – статический анализатор, доказывающий корректность работы с памятью. Если программа скомпилировалась – целый класс ошибок физически невозможен.

**Zero-cost abstractions** – высокоуровневые конструкции без накладных расходов. Ты не платишь за то, что не используешь.

**Fearless concurrency** – система типов, исключающая гонки данных на этапе компиляции.

Скептик скажет: "Звучит как маркетинг, но работает ли это на практике?"

Работает. Три крупнейшие технологические компании публикуют метрики внедрения Rust – и результаты говорят сами за себя.

### Google Android

Google внедряет Rust в Android с 2019 года. К 2025 году платформа содержит уже около 5 миллионов строк Rust-кода. Результаты:

- **Плотность уязвимостей памяти**: примерно 0.2 на миллион строк кода. За все время обнаружена одна потенциальная уязвимость – и ту исправили до релиза.
- **Откаты изменений**: в 4 раза реже.
- **Время code review**: на 25% меньше.
- **Количество ревизий кода**: на 20% меньше.

В 2025 году в Android добавили больше строк на Rust, чем на любом другом системном языке. Доля уязвимостей памяти впервые за историю платформы опустилась ниже 20%.

Джефф Ван дер Ступ из Google: *"Более безопасный путь оказался также и более быстрым."*

### Microsoft Azure

Марк Руссинович, CTO Microsoft Azure, несколько лет назад ввёл директиву: никакого нового системного кода на legacy-языках. Результаты переписывания:

**DirectWrite Core** (парсер шрифтов Windows): 152 000 строк Rust. Два разработчика, шесть месяцев. Производительность рендеринга текста выросла примерно на 5–15%  – без специальных оптимизаций, просто за счёт переписывания.

**Azure Data Explorer**: 350 000 строк Rust. Обрабатывает петабайты данных ежедневно, миллиарды запросов.

**Hyperlight**: запуск микро-виртуальных машин за 0.9 миллисекунды.

**OpenVMM**, **Caliptra**, **Azure Integrated HSM** – критическая инфраструктура безопасности, полностью на Rust.

Это уже не просто эксперимент. Последнюю пару лет начинает ржаветь не только Windows, но и весь низкоуровневый софт вокруг него. В 2023 появился первый системный вызов (syscall) ядра Windows, написанный на Rust. А в релизе Windows 11 24H2 в графической подсистеме работает полноценный Rust-драйвер win32kbase_rs.sys для управления регионами памяти в GDI – а это перехват целого класса LPE-уязвимостей. Стек печати защищён Rust-парсерами – PrintNightmare закрыта на архитектурном уровне. Но самое важное: Microsoft выпустила Windows Driver Kit с официальной поддержкой Rust. Это означает, что любой разработчик антивируса, драйвера устройства или чипсета может писать код ядра на безопасном для памяти языке.

Microsoft также разрабатывает инструменты автоматической миграции legacy-кода:
- **Eurydice** – транспилятор для верифицированного криптографического кода с сохранением формальной верификации
- **GraphRAG** – использование LLM с иерархическим retrieval для автоматического перевода кода

Руссинович: *"Чем быстрее мы сможем мигрировать, тем лучше. Мы на 100% за Rust."*

### Adobe

Adobe управляет кодовой базой в 78 миллионов строк legacy-кода, огромный зоопарк языков и скриптов. Полное переписывание невозможно – компания выбрала стратегию инкрементального перехода.

Шон Пэрент, Senior Principal Scientist: *"Мы портировали компонент на Rust. Производительность составляет около 85% от legacy-реализации. В некоторых случаях Rust-версия выигрывает."*

Главный публичный проект – **C2PA** (Coalition for Content Provenance and Authenticity): библиотека для проверки подлинности контента и борьбы с deepfake. Полностью на Rust, открытый исходный код.

По внутренним данным Adobe: разработчики достигают продуктивности на Rust примерно за 2 месяца. Две трети из них чувствует себя достаточно уверенно, чтобы работать над реальными продуктами.

Дэвид Санкель, Principal Scientist Adobe: *"Положить лучшие инструменты в руки наших инженеров – значит создать лучшие продукты для клиентов."*

## Для кого эта книга

Давай сразу проясним: **это не введение в Computer Science.**

Книга не учит программировать с нуля. Если термины «аргумент функции», «область видимости» или «итерация» вызывают у тебя вопросы – лучше начать с более простых вводных курсов, а потом вернуться сюда.

Материал рассчитан на инженера, который:

1.  **Уже имеет опыт разработки.** Неважно на чем написаны твои прошлые проекты. Важно, что ты уже умеешь превращать алгоритмы в код и сталкивался с реальными задачами.
2.  **Понимает устройство памяти.** Хотя бы на интуитивном уровне: чем данные в стеке (stack) отличаются от данных в куче (heap) и почему это важно.
3.  **Не боится терминала.** Работа с инструментами Rust происходит преимущественно в командной строке.

Rust – в первую очередь системный язык. Он снимает слой "магии" и заставляет учитывать то, что обычно заметается под ковер. Если ты готов к этому – добро пожаловать.

Структура книги необычна. Она состоит из **Ядра** и **Специализированных приложений**.

### Ядро (Части I–VIII)
Это прямой путь от синтаксиса до продакшена. Мы будем писать то, что пишут 90% Rust-разработчиков: CLI-утилиты, веб-сервисы, работу с базами данных и распределенные системы. Это обязательная программа.

### Приложения F и G (Hardcore Mode)
Это "кроличья нора" для тех, кому скучно просто перекладывать JSON'ы.
*   **Приложение F**: Эволюционные алгоритмы и симуляции жизни.
*   **Приложение G**: Инженерная модель сознания (Global Workspace Theory).

Эти главы используют Rust для моделирования сложных систем. Они опциональны. **Ты можешь стать отличным Rust-разработчиком, вообще не открывая их.** Но если тебе интересно, как создать виртуальную популяцию или смоделировать механизм внимания – ищи ссылки вида `→ Приложение F.2` в конце глав ядра.

### Фильтры качества
В конце каждой части есть чек-лист «Фильтр качества». Это не просто список тем, а конкретные навыки. Например: *"Нарисовать диаграмму памяти для `&mut T` за 30 секунд"*. Не проходи дальше, пока не поставишь все галочки.

Такая структура выбрана не случайно. Задача этой книги – провести тебя через все необходимые этапы максимально эффективно. Здесь не будет теории ради теории. Каждая глава – это проект. Каждый проект – шаг к следующему уровню сложности.

Но прежде чем писать код, нужно настроить окружение. Экосистема Rust славится своим удобством, и скоро ты убедишься в этом лично.

## Установка инструментов

### rustup – менеджер версий Rust

Официальный способ установки Rust – через rustup.

На Linux/macOS:

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

На Windows:

Установи Visual Studio 2026 Community. При установке выбери опцию "Desktop development with C++"). Затем скачай и запусти [rustup-init.exe](https://rustup.rs).

После установки перезапусти терминал и проверь:

```bash
rustc --version
cargo --version
```
Если обе команды отвечают – Rust установлен.
rustup управляет toolchain'ами. Стабильная версия (stable) – твой основной инструмент. Для некоторых продвинутых возможностей понадобится nightly:

```bash
rustup toolchain install nightly
rustup default stable
```

Переключение между версиями:

```bash
rustup override set nightly  # для текущей директории
rustup default nightly       # глобально
```

### Cargo – сердце экосистемы

Cargo – это одновременно:
- Менеджер зависимостей
- Система сборки
- Запуск тестов
- Генератор документации
- Публикация пакетов

Один инструмент вместо зоопарка. Одна команда – одна задача.

Ключевые команды:

```bash
cargo new project_name       # создать новый проект
cargo build                  # собрать (debug)
cargo build --release        # собрать (release, с оптимизациями)
cargo run                    # собрать и запустить
cargo test                   # запустить тесты
cargo check                  # проверить без генерации бинарника (быстро)
cargo doc --open             # сгенерировать документацию и открыть
cargo clippy                 # статический анализатор (линтер)
cargo fmt                    # форматирование кода
```

### IDE: Zed

**Zed** – редактор, написанный на Rust, для разработки на Rust (и не только). Быстрый, минималистичный, со встроенной поддержкой языка из коробки.

Установка: [zed.dev](https://zed.dev)

Zed автоматически определяет Rust-проекты и активирует rust-analyzer. Никакой дополнительной настройки не требуется – открой папку с `Cargo.toml` и работай.

Полезные горячие клавиши:

| Действие | macOS | Linux |
|----------|-------|-------|
| Перейти к определению | `Cmd+Click` или `F12` | `Ctrl+Click` или `F12` |
| Найти все ссылки | `Shift+F12` | `Shift+F12` |
| Переименовать символ | `F2` | `F2` |
| Показать действия (fix) | `Cmd+.` | `Ctrl+.` |
| Палитра команд | `Cmd+Shift+P` | `Ctrl+Shift+P` |

Настройки в `~/.config/zed/settings.json`:

```json
{
  "lsp": {
    "rust-analyzer": {
      "initialization_options": {
        "check": {
          "command": "clippy"
        }
      }
    }
  }
}
```

**Альтернативы:**

- **VS Code + rust-analyzer** – популярный выбор, расширение из marketplace
- **RustRover** – полноценная IDE от JetBrains с отладчиком и профилировщиком
- **Neovim + rust-analyzer** – для тех, кто живет в терминале

rust-analyzer (используется всеми перечисленными) дает:
- Автодополнение с учетом типов
- Inline-подсказки типов и lifetime'ов
- Go to definition/implementation
- Rename refactoring
- Expand macro (увидеть, во что раскрывается макрос)

## Первый проект: Hello World

```bash
cargo new hello_rust
cd hello_rust
```

Структура проекта:

```
hello_rust/
├── Cargo.toml
└── src/
    └── main.rs
```

`Cargo.toml` – манифест проекта:

```toml
[package]
name = "hello_rust"
version = "0.1.0"
edition = "2024"

[dependencies]
```

`edition = "2024"` – версия языка. Rust выпускает новые editions раз в три года (2015, 2018, 2021, 2024). Editions позволяют вводить изменения без потери обратной совместимости: старый код компилируется со старой edition, новый – с новой. Crate'ы разных editions полностью совместимы друг с другом.

`src/main.rs`:

```rust
fn main() {
    println!("Hello, Rust!");
}
```

Запуск:

```bash
cargo run
```
Вывод:

```
   Compiling hello v0.1.0 (.../hello_rust)
    Finished dev [unoptimized + debuginfo] target(s) in 0.50s
     Running `target/debug/hello`
Hello, world!
```

`println!` – макрос, не функция. Восклицательный знак – индикатор макроса. Макросы в Rust – мощный инструмент метапрограммирования. `println!` принимает format string с плейсхолдерами:

```rust
fn main() {
    let name = "мир";
    let answer = 42;
    println!("Привет, {}! Ответ: {}", name, answer);
    println!("Debug: {:?}", (name, answer));
    println!("Pretty debug:\n{:#?}", vec![1, 2, 3]);
}
```

`{}` – Display formatting (для пользователя)
`{:?}` – Debug formatting (для разработчика)
`{:#?}` – Debug с pretty-print

## Syntax Capsule: основы синтаксиса

### Переменные

```rust
let x = 5;           // неизменяемая переменная
let mut y = 10;      // изменяемая переменная
y = 15;              // ok
// x = 6;            // ошибка компиляции
```

По умолчанию переменные **неизменяемы** (immutable). Это не константы – это переменные, которые нельзя изменить после инициализации. Для изменяемой переменной нужен `mut`.

Почему? Неизменяемость по умолчанию делает код безопаснее и понятнее. Если переменная не меняется – ее значение можно отследить без чтения всего кода.

### Типы

Rust статически типизирован, но компилятор часто выводит типы автоматически:

```rust
let x = 5;              // i32 (целое число по умолчанию)
let y = 3.14;           // f64 (число с плавающей точкой)
let flag = true;        // bool
let ch = 'A';           // char (Unicode символ)
let text = "hello";     // &str (строковый срез)
```

Явное указание типа:

```rust
let x: i32 = 5;
let y: f64 = 3.14;
```

Основные числовые типы:
- `i8`, `i16`, `i32`, `i64`, `i128` – знаковые целые
- `u8`, `u16`, `u32`, `u64`, `u128` – беззнаковые целые
- `f32`, `f64` – числа с плавающей точкой
- `usize`, `isize` – зависят от архитектуры (32/64 бит)

### Функции

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b    // без точки с запятой = возвращаемое значение
}

fn greet(name: &str) {
    println!("Hello, {}!", name);
}

fn main() {
    let result = add(5, 3);
    greet("Rust");
}
```

**Ключевые моменты:**
- Типы параметров обязательны
- `->` указывает тип возвращаемого значения
- Последнее выражение без `;` – возвращаемое значение
- `return` можно использовать для раннего выхода

### Строки

Два основных типа:

```rust
let s1: &str = "hello";                  // строковый срез (string slice)
let s2: String = String::from("hello");  // владеющая строка
```

`&str` – ссылка на строковые данные (неизменяемая, часто в коде программы).
`String` – владеющий тип, может расти и изменяться.

Подробности – в Главе 5. Пока используй `&str` для литералов и `String::from()` если нужна владеющая строка.

## Что дальше?

Ты настроил окружение и запустил первую программу. Теперь у тебя есть все необходимое, чтобы начать писать реальный код.

Rust требует инвестиций на старте. Компилятор будет отвергать код, который на первый взгляд кажется рабочим. Это не баг, а фича. И когда ты это прочувствуешь, ты получишь:

- "Если компилируется – работает" – не шутка, а ежедневная реальность
- Рефакторинг без страха – компилятор найдет все места, которые нужно изменить
- Многопоточность без бессонных ночей – система типов исключает гонки данных
- Производительность без жертв – ты получаешь и скорость, и безопасность

В Главе 1 мы напишем первый настоящий проект и познакомимся с управлением потоком выполнения: условиями, циклами и коллекциями.
